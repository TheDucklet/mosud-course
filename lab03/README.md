## Что делает работа

Задание показывает, как словесное условие переводится в выражение реляционной
алгебры и затем в SQL: выборку `σ` (в SQL — `WHERE`), проекцию `π` (список столбцов
`SELECT`) и переименование `ρ` (`AS`). Скрипт содержит исходную реализацию, вариант
с разбитым предикатом, вариант с ранним сокращением атрибутов и проверку появления
дубликатов в проекции.

## Исходное отношение и атрибуты

Отношение `olist.products(product_id, product_category_name, product_length_cm,
product_height_cm, product_width_cm, ...)`, всего **32 951** кортеж. Используемые
атрибуты: `product_id`, `product_category_name`, `product_length_cm`,
`product_height_cm`, `product_width_cm`.

## Выражение реляционной алгебры

```
π_{product_id, product_category_name, product_length_cm, product_height_cm, product_width_cm}(
    σ_{product_category_name ≠ NULL ∧ product_length_cm · product_height_cm · product_width_cm > 20000}
        (products)
)
```

Объём — вычисляемый атрибут (не хранится в таблице), поэтому он появляется внутри
предиката и вычисляется из трёх столбцов.

## Как устроены блоки

1. **Исходное отношение.** Показывает таблицу, используемые атрибуты и число NULL
   в них: категория отсутствует у 610 товаров, а размеры — у 2. NULL в размерах
   важно: `NULL · ...` даёт `NULL`, и такой кортеж не проходит предикат `> 20000`
   (он не «истина» в трёхзначной логике).
2. **Исходная реализация.** `WHERE` — это `σ` с составным предикатом, список
   столбцов — `π`. Условие `product_category_name IS NOT NULL` записано явно, чтобы
   предикат был трёхзначным только из-за размеров.
3. **Мощность результата.** `count(*) = count(DISTINCT product_id) = 7607`.
4. **Разбиение предиката.** Поскольку `σ_{p ∧ q} = σ_p(σ_q(R))`, два последовательных
   фильтра дают то же самое. Это свойство дизъюнктивности/коммутативности выборки
   по `∧`.
5. **Эквивалентность.** Сравнение через `EXCEPT` в обе стороны, потому что `ORDER BY`
   без гарантии порядка не является критерием равенства отношений.
6. **Раннее сокращение атрибутов.** В подзапросе сразу оставляем только `product_id`,
   `product_category_name` и вычисляемый объём; лишние столбцы (название, длина описания,
   вес, фото) не проходят через промежуточное отношение. Это прообраз оптимизации
   «проекция внутрь дерева».
7. **Переименование `ρ`.** `product_id AS pid, product_category_name AS category,
   ... AS volume_cm3` — пример `ρ` над атрибутами. Соединение с фильтром даёт тот же
   результат.
8. **Эквивалентность раннего сокращения.** Также проверяется `EXCEPT` в обе стороны.
9. **Дубликаты.** Результат с `product_id` (ключ) содержит уникальные строки, поэтому
   `SELECT` и `SELECT DISTINCT` совпадают: 7 607 против 7 607. Но если спроектировать
   только `category`, 7 607 строк схлопнутся до 65 различных категорий — проекция
   без ключа обязательно порождает дубликаты.
10. **Пример категорий с дубликатами.** Топ-5 категорий, где число товаров в
    результате больше одного.

## О дубликатах и эквивалентности (3–5 предложений)

В математической модели отношение — это множество, поэтому проекция `π` сразу
удаляет повторяющиеся кортежи; в SQL `SELECT` сохраняет кратность и ведёт себя как
мультимножество. Здесь результат содержит ключ `product_id`, и повторяющихся строк
не возникает, так что `SELECT` и `SELECT DISTINCT` дают одинаковые 7 607 строк.
Но стоит убрать ключ из проекции (оставить только категорию), как дубликаты
появляются: 7 607 строк соответствуют 65 различным категориям.
Эквивалентность исходного и разбитого выражений проверена через `EXCEPT` в обе
стороны, а не визуальным сравнением, потому что порядок строк без `ORDER BY` не
является свойством отношения.

## Контрольные вопросы

1. **Какие свойства выборки позволяют менять порядок нескольких фильтров?**
   Коммутативность (`σ_p(σ_q(R)) = σ_q(σ_p(R))`) и идемпотентность
   (`σ_p(σ_p(R)) = σ_p(R)`), а также дистрибутивность относительно `∧`:
   `σ_{p∧q}(R) = σ_p(σ_q(R))`. Плюс тот факт, что выборка не меняет схему отношения,
   поэтому фильтры можно применять в любом порядке.
2. **Почему проекция в математической модели устраняет повторяющиеся кортежи, а
   SELECT в SQL — нет?** Отношение по определению — множество, и в нём не может быть
   двух одинаковых кортежей; поэтому `π_X(R)` сразу строится как множество. SQL
   допускает мультимножества ради эффективности (удаление дубликатов стоит досортировки
   или хеширования), поэтому по умолчанию `SELECT` сохраняет кратность, а `DISTINCT`
   нужно указывать явно.
3. **Что означает замкнутость операций реляционной алгебры?** Результат каждой
   операции — снова отношение с той же структурой (набор атрибутов и кортежей),
   поэтому результат одной операции можно подать на вход другой, строя деревья
   произвольной глубины. В SQL это выражается подзапросами и CTE: подзапрос
   возвращает таблицу, с которой можно выполнять новые выборки и проекции.

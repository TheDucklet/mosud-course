## Как поднять базу

1. Положить CSV-файлы Olist в каталог `data/olist/` (в git он не входит).
2. Из корня репозитория выполнить `docker compose -f lab01/docker-compose.yml up -d` — поднимется PostgreSQL 17 с базой `olist`, пользователем `student`/`student` и примонтированными данными по пути `/data/olist`.
3. Подключиться к базе `olist` и выполнить по порядку: `lab01/schema.sql` → `lab01/import.sql` → `lab01/constraints.sql` → `lab01/analyze.sql` → `lab01/check.sql`.

Строки подключения для DBeaver (подключение к тому же контейнеру):

| Поле | Значение |
|---|---|
| Host | `localhost` |
| Port | `5432` |

| Username | `student` |
| Password | `student` |

## Как выполнять работы

1. Открыть в DBeaver подключение к `olist`.
2. Открыть `labNN/labNN.sql` и выполнить его целиком (Alt+X «Execute SQL script»), либо выполнять блоки по одному (Ctrl+Enter) — каждый блок начинается со строки-комментария `-- <что он делает>`.
3. Порядок работ — по возрастанию номера каталога: каждая следующая работа опирается на схему `lab`, созданную предыдущими (работа 9 создаёт нормализованные таблицы, работа 11 пересоздаёт `lab.inventory`, и т. д.).
4. Работу 12 выполняют в двух окнах: сначала `lab11/lab11.sql` (подготовка), затем `lab11/session_a.sql` в первом окне и `lab11/session_b.sql` во втором — шаг за шагом, как указано в `lab11/README.md`.

Все скрипты идемпотентны: повторный запуск даёт тот же результат. Работы 2–8, 10, 13 и 14 только читают `olist`; данные в схему `olist` не пишутся никогда — все изменения происходят в схеме `lab`.

## Требования к содержанию скриптов

- Внутри скриптов нет пошаговых комментариев к логике: каждая работа — это пять строк шапки (автор, группа, вариант и практика, тема) и одна строка `-- <описание>` перед каждым смысловым запросом.
- Подробное объяснение — в `README.md` соответствующего каталога: что делает работа, как устроены блоки, какие числа получены на данных Olist, ответы на контрольные вопросы раздатки.
- Запрещённых конструкций нет: используются обычные SQL-операторы, DDL, представления, CTE (в том числе рекурсивные), транзакции, индексы, `EXPLAIN (ANALYZE, BUFFERS)`.
